# FAME learning platform

Start with [START-HERE.md](START-HERE.md) for a nontechnical setup guide. Deployment details are in [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Commands

| Command | Purpose |
| --- | --- |
| `npm ci` | Install locked dependencies |
| `npm run dev` | Development app and API on port 4173 |
| `npm run build` | Compile the frontend to `dist/` |
| `npm start` | Serve built frontend plus API |
| `npm run admin` | Privately create the first owner account |
| `npm test` | Account/payment/access integration tests |
| `npm run check` | Server JavaScript syntax checks |
| `npm run backup` | Consistent SQLite backup |

## Structure

- `src/`: responsive website, student dashboard, lesson experience and owner UI.
- `server/`: auth/session handling, database, catalogue, orders, payment verification, progress and email queue.
- `public/`: founder photo, favicon and public assets.
- `private-media/`: non-public course recordings; never part of the public static directory.
- `scripts/`: owner account setup and database backup.
- `tests/`: security and integration tests using an isolated temporary SQLite database and simulated Razorpay API responses.
- `dist/`: prebuilt frontend, also regenerated by `npm run build`.

## Editing content

Draft starter courses initialise only on a fresh database. Editing `server/seed.js` does not overwrite an existing course catalogue. Use Owner dashboard for existing programmes. Portfolio copy lives in `src/main.jsx`; branding and responsive styles in `src/styles.css`.

## Security boundaries

Every protected API checks the session and course entitlement. Sessions use random opaque tokens, SHA-256 storage, HttpOnly cookies and SameSite=Lax; production adds Secure cookies. Writes require an exact allowed origin and a session-bound CSRF token. Passwords use salted scrypt. SQL is parameterised. Authentication and payment endpoints have database-backed rate limits. Owner privileges are never accepted from a signup body. Course content is rendered as text, not raw HTML.

Demo completion is unavailable in Razorpay mode and production; prior demo orders do not grant live access. Production startup fails with demo mode, HTTP origin, missing Razorpay secrets or missing SMTP configuration. Live checkout also requires a verified account, published non-sample course and configured business policies.

External video URLs are visible to authorised learners. Use local protected media or a signed playback provider when recordings must not have reusable public URLs. No DRM is claimed.

## Design and conversion

The page follows a founder-led path: relevant experience → three FAME decisions → appropriate programme → transparent curriculum and price → account → payment → learning. It uses one primary enrolment action per programme, mobile layouts, free lesson previews and a short checkout. No invented testimonials, fake scarcity, earnings claims or customer financial details are used. Conversion rates require measurement with actual traffic; no rate is promised.
